## 二、需求背景

### 2.1 业务现状与问题

TradingAgents-CN 的 A 股数据采集当前依赖四条通道：tushare、akshare、baostock、东财直连。存在以下痛点：

1. **高频数据有积分墙**：tushare 的分钟线、tick、实时行情等域需要 2000~5000 积分（年费数千元），低积分账户在回退链中实际不可用——**分时与 tick 两个域在多数部署中无有效源**。
2. **免费源稳定性差**：akshare、东财直连均为网页接口逆向，反爬升级即批量失败。
3. **回退链纵深不足**：A股行情域在 tushare 积分不足的部署中，有效源仅剩 akshare/baostock 两条同质通道（同为爬虫/公开接口）。
4. **多智能体分析的数据预注入**（`app/engine/orchestrator/agents.py` 的 `build_tool_data`）依赖库内数据新鲜度，源不稳直接导致分析报告数据缺失。

### 2.2 需求来源

用户提出：参考 `E:\openclaw\StockQuant` 项目（`src/data` 目录）已验证的 QMT 采集实现，为 TradingAgents-CN 接入 QMT 数据采集；v1.2 明确要求覆盖 tick 与分时数据、仅用本地直读模式。

### 2.3 QMT 是什么、为什么能解决

QMT（迅投 miniQMT）是券商提供的量化终端，向签约用户提供本地全息行情：日线/分钟线/tick 历史、合约列表、板块、财务 8 表、分红复权因子。本方案仅采用其 **datadir 本地数据目录直读**通道——QMT 客户端运行时通过「盘后自续下载任务」把全量行情落到本地 `datadir` 目录，StockQuant 已逆向其二进制格式（64B K 线 / 144B tick / LevelDB 分红表），可**纯文件 IO 解析、零 API 依赖、零 `xtquant` 库依赖**。特点：

- **无积分墙**：数据随客户端本地缓存产出，不按次计费，恰好补齐分时/tick 两个无源域；
- **质量高**：交易所授权行情（区别于网页爬取），且带拒读级自检（格式漂移时整文件拒读，绝不产出错误值）；
- **硬约束**：仅 Windows；需国金 QMT 客户端运行并配置下载任务；**datadir 为盘后下载产物，无盘中实时性**——这是 v1.2 移除 RPC 通道后的明确边界（见 4.2）。

### 2.4 核心问题陈述（一句话）

> TradingAgents-CN 的 A 股数据采集在免费源（akshare/东财）稳定性差、tushare 高频域受积分限制的情况下，分时与 tick 域长期无有效数据源、行情域回退链纵深不够；QMT datadir 本地直读提供了一条无积分门槛、高可靠的历史数据通道，且能以完全一致的数据格式并入现有数据平台。

## 三、目标与成功指标

### 3.1 产品目标

本期将 QMT（datadir 直读）作为 **A 股市场（沪深）的第 5 条数据源**接入现有数据平台：实现 `QmtProvider`/`QmtAdapter` 注册进能力矩阵与回退链，覆盖**日线、分时（1m/5m）、tick、合约列表**等历史数据域（M1 先交付日线/合约列表，M2 补齐分时/tick），全部数据以既有标准 Schema 入库。

### 3.2 成功指标（四要素）

| 指标 | 目标值 | 口径与公式 | 统计周期 | 排除项 |
|------|--------|-----------|----------|--------|
| QMT 源采集成功率 | ≥ 98% | `source_health` 中 qmt 源 `success_count / (success_count + failure_count)`，按交易日统计 | 每交易日 | datadir 未产出（下载任务未运行）的计划内等待 |
| 日线域入库时效 | 收盘后 ≤ 30 分钟 | 从 datadir 当日分区就绪到 `daily_quotes` 当日数据写入完成的中位时长 | 每交易日 | 节假日、datadir 产出晚于 22:00 的交易日 |
| 全市场日线覆盖率 | ≥ 99% | 当日 `daily_quotes` 有记录的沪深 A 股数 / 合约列表总数（剔除停牌，停牌股以 `suspend_flag` 标注计入分母） | 每交易日 | 上市首日无行情的新股 |
| 回退链演练通过 | 1 次 | 人为熔断 tushare 后，`daily_quotes` 读取请求经 FallbackRouter 自动切至 qmt 源成功的比例 = 100% | 上线前一次性验收 | — |
| 分时域入库时效（M2 起） | 收盘后 ≤ 90 分钟 | 从 datadir 当日分时就绪到 `intraday_quotes` 写入完成的中位时长（**估算值**，待 T-2 实测下载任务产出时刻后校准） | 每交易日 | 节假日 |
| tick 自检覆盖率（M2 起） | ≥ 95% | 单日 tick 采集后自检：有数据的合约数 / 应有合约数（沿用 StockQuant `_tick_self_check` 阈值），自检报告落 `sync_events` | 每交易日 | 停牌、无成交合约 |

### 3.3 反指标（不允许牺牲）

- **现有源零退化**：接入 QMT 不得降低 tushare/akshare/baostock 现有采集成功率；
- **数据格式一致性（D-5）**：QMT 数据必须经 Adapter 转换落入既有标准域 Schema 与 MongoDB 集合，通过 `Normalizer`/`Validator` 校验；**禁止**新建 Parquet/文件存储、禁止绕过标准 Schema 直写、禁止「QMT 专用表」旁路；
- **数据正确性**：datadir 文件四级自检不通过时必须整文件拒读，绝不写可疑值入库；
- **架构红线**：不允许绕过 `DataInterface`/`FallbackRouter` 建立第二条消费通道（AGENTS.md 数据层约束）。

## 四、范围定义

### 4.1 本期包含

| 模块 | 内容 |
|------|------|
| 直读层 | `datadir` 本地直读管理器（移植 StockQuant `datadir_reader`）：纯文件 IO 解析、四级自检、路径监控、数据新鲜度检查；零 `xtquant` 依赖 |
| 数据域 | 日线（含复权因子）、合约列表/详情（P0）；分时 1m/5m（`intraday_quotes`）、tick（新域 `tick_quotes`）、指数日线、财务、分红复权、交易日历（P1）；板块（P2，见 4.2） |
| 格式一致性（D-5） | Adapter 字段映射表（QMT 字段 → 项目标准 Schema 字段）、Validator 强校验、统一入既有 MongoDB 集合 |
| 平台接入 | `app/data/sources/cn/qmt/` Provider+Adapter、能力矩阵/优先级/限流 YAML 注册（含 `tick_quotes` 新域注册）、CN 市场工厂挂载 |
| 调度 | worker 盘后采集任务（日线→复权→分时→tick→指数/财务 顺序） |
| 配置与运维 | 环境变量开关、Web UI 数据源管理页配置 datadir 路径与保留策略（D-4）、`get_source_health` 健康上报、tick 保留期（TTL）管理 |

### 4.2 本期不做的事

| 项 | 不做原因 | 后续计划 |
|----|----------|----------|
| 交易功能（xttrader 下单/查询） | 与数据采集目标无关，且引入交易资质与资损风险 | 永久不做（数据源边界） |
| **QMT 实时快照（盘中 `market_quotes`）** | **D-7 的连带边界**：datadir 是客户端盘后下载任务的产物，盘中无实时性；既有三个实时源（tushare → akshare 东财 → akshare 新浪）继续负责实时快照，回退深度不变 | 若后续验证客户端盘中持续下载场景（datadir 准实时更新），可重新评估，记后续版本池 |
| 实时订阅推送（`subscribe_quote`/`subscribe_whole_quote`） | 依赖 xtquant RPC 连接，与 D-7 冲突；现有「定时同步+按需刷新」模型暂无盘中推送需求 | 与上一项合并评估 |
| xtquant/miniqmt RPC 直连通道 | **D-7 明确移除**：避免 `xtquant` 版本与客户端绑定、多端登录互踢等问题；datadir 通道即可覆盖全部历史数据域 | 不再做（已由 datadir 替代） |
| 港股/美股 QMT 源 | QMT datadir 行情范围以沪深为主，价值/成本比低 | 视需求立项 |
| 北交所（BSE）采集 | 参考 StockQuant 实践：剔除北交所标的，避免必然失败的采集 | 后续版本池 |
| 分离式采集代理（跨机推送） | 属部署形态扩展，MVP 为同机部署（D-1）；datadir 直读天然适合分离部署（采集机只需文件访问权） | M3（架构不设阻碍） |
| 板块（行业/概念）数据 | 映射 `basic_info` 扩展字段或新域需先过 Schema 评审 | FR-08 仅输出评审结论文档，M3 立项 |

### 4.3 边界说明

- QMT 是**数据源**而非**存储**：所有 QMT 数据经 Adapter 标准化后写入既有 MongoDB 集合，不新建 Parquet 湖（D-5）；唯一新增的集合是 `tick_quotes` 新标准域对应的集合（按 `get_collection_name` 市场分表规则命名）；
- 与 StockQuant 的关系是**移植代码与经验**（datadir 解析器、缺口管理、复权建模），不是系统集成，两项目不共享运行时；
- QMT 数据的**时效上限 = datadir 产出时刻**：调度窗口起点取决于国金客户端下载任务的实际完成时间（T-2 待实测），3.2 中分时时效为估算值；
- datadir 直读通道依赖 QMT 客户端「盘后自续下载任务」配置，该配置写入 `docs/` 部署指南并在健康页提供新鲜度告警。

### 5.3 场景三层次

- **主流程**：交易日盘后国金客户端下载任务产出 datadir → 调度触发（新鲜度探测就绪后）→ datadir 直读 → Adapter 按标准 Schema 标准化 → 入库 MongoDB 既有集合 → `Reader` 新鲜度判定转为 FRESH → 分析预注入使用。
- **分支流程**：库内数据 STALE 且在冷却窗口外 → `DataRefreshService` 触发 qmt 按需刷新（读 datadir）；datadir 当日未产出 → 调度等待重试（有截止时刻）后转缺口登记。
- **异常流程**：datadir 路径不可用 → 熔断器开启 → 回退链交由既有源，`sync_events` 记录原因；datadir 文件自检不通过 → 整文件拒读（绝不写错误值）→ 登记缺口待补；tick 日体积超限 → 自动暂停 tick 采集并告警，其余域不受影响。

## 七、流程与交互说明

### 7.1 主采集流程（节点 → 判断 → 分支）

```
调度触发（交易日，自 15:30 起每 10 分钟探测）
  → 自检：是交易日？ ─否→ 跳过，记录 sync_events(non_trading_day)
  → 自检：datadir 当日分区就绪？ ─否→ 等待重试（截止 22:00）─超时→ 缺口登记 + 告警
  → 自检：文件四级自检 ─失败→ 整文件拒读 → 缺口登记 →（其余文件继续）
  → QmtProvider 按 datadir 分区直读（分块、断点续传）
  → QmtAdapter 字段映射 → Normalizer 标准化（17 域 + tick_quotes 标准 Schema）
  → Validator 校验 ─失败→ 拒写该批次 + 记录 SourceHealthMonitor
  → 写 MongoDB 既有集合（按市场分表）→ 更新 sync_checkpoints
  → 缺口检测 → 有缺口且补采轮次未超限 → 补读历史 datadir 分区（≤3 轮）
  → tick 域附加：覆盖率自检（≥95%）+ TTL 过期分区清理 + 写入量阈值检查
```

### 7.2 状态机：QMT 源状态（datadir 视角）

| 状态 | 触发事件 | 迁移条件 | 允许操作 |
|------|----------|----------|----------|
| `disabled` | QMT_ENABLED=false 或未配置 | 开关打开且配置自检通过 → `idle` | 仅配置编辑 |
| `idle` | 开关打开 | 首次采集触发 → `checking` | 配置编辑、配置自检 |
| `checking` | 采集触发/手动自检 | 路径可读 + 四级自检通过 + 分区就绪 → `ready`；任一失败 → `unavailable` | 三层检查、超时退出 |
| `ready` | datadir 就绪 | 三层检查发现路径失效/自检失败 → `unavailable`；最新分区落后 ≥ 1 交易日 → `ready`（带 stale 标记并告警）；开关关闭 → `disabled` | 全部历史域采集、TTL 清理 |
| `unavailable` | 路径失效/自检失败 | 周期重检（默认每 5 分钟）通过 → `ready` | 仅健康上报；不产生采集任务 |

状态单向流转：`disabled` 为唯一可人工回退态，其余异常态均通过周期重检自动恢复，不允许手工置 `ready`。

### 7.3 部署形态

```
【模式 A：同机直读（本期，已确认 D-1 + D-7）】
Windows 部署机
  ├─ 国金 QMT 客户端（用户正常登录使用；配置「盘后自续下载任务」产出 datadir）
  ├─ TradingAgents-CN（app/ 内嵌 QmtProvider，纯文件 IO 直读 datadir，零 xtquant 依赖）
  └─ MongoDB / Redis（本机或内网）

【模式 B：分离采集（M3 预留，本期不做）】
Windows 采集机（仅 QMT 客户端 + datadir；或通过网络共享暴露 datadir 目录）
        │ datadir 文件同步 / 轻量直读代理推送
服务器（Linux/Docker：TradingAgents-CN + MongoDB + Redis）
```

datadir 直读为纯文件 IO，天然适配模式 B（只需文件访问权，无客户端 API 耦合）；模式 B 仅需在 `QMT_DATADIR` 指向网络路径或增加同步环节，`QmtProvider` 接口无差异。

### 7.4 交互说明（Web UI 数据源管理页）

- **正常态**：qmt 卡片显示「就绪 · 最新分区 2026-10-17 · 最近采集 xx 分钟前 · 今日成功率 99.2%」；
- **空状态**：未配置时显示「未启用」，引导至配置项说明，不显示报错；
- **配置编辑**：卡片内可编辑 datadir 路径、tick 保留期、就绪截止时刻（D-4）；保存写入 Mongo 配置并触发一次自检给出结果提示；未配置项回显 ENV 缺省值并标注「来自环境变量」；
- **错误态**：分三种文案（datadir 路径不存在 / 文件自检失败（含具体文件）/ 数据停更），各附一行修复指引；
- **边界**：非交易时段自检仍可执行（检查的是 datadir 文件而非行情可用性）；「最新分区时间」与交易日历比对展示，停更一目了然。

## 九、验收标准

- **整体验收口径**：以第六节各 FR 的 GWT 验收标准为准，逐条通过；
- **数据验收**：`source_health` 中 qmt 成功率 ≥ 98%（连续 10 个交易日）；`sync_events` 无未归因失败；日线覆盖率 ≥ 99%（连续 10 个交易日）；M2 起分时时效与 tick 自检覆盖率达标；
- **格式一致性验收（D-5）**：抽样比对 qmt 来源与 tushare 来源的同域记录——同集合、同 Schema、同字段类型，无 QMT 专用旁路存储；
- **回退验收**：3.2 节「回退链演练」通过（熔断 tushare 后 daily_quotes 经 qmt 自动恢复）；
- **回归验收**：QMT_ENABLED=false 时，现有 4 源采集成功率与数据新鲜度不劣化（对照开启前 5 个交易日基线）；
- **边界验收**：附录异常处理清单逐项通过。

### 10.4 灰度与回滚

- **灰度**：`QMT_ENABLED` 默认 false；开启后先仅注册 `daily_quotes` 单域（回退链末位），观察 3 个交易日再按域逐个纳入回退链；tick 域在 M2 内单独灰度（先小范围标的验证体积实测，再放开全市场）；
- **回滚**：关闭 `QMT_ENABLED` 即完成回滚——qmt 从所有候选链移除，既有源链不受影响；tick 域可独立关闭（`tick_quotes` 域开关）不影响其他域；已入库的 QMT 数据带来源标记，保留不清理（只读无害），如需清除按 `source=qmt` 条件删除并登记 `sync_events`。

## 十一、合规注意事项（金融领域专项）

> 本节为强监管领域提示，具体以法务意见为准。

1. **行情授权范围**：QMT 行情经券商/迅投授权，通常**仅限签约用户本人研究使用**。本方案限定为个人自部署自用场景，不提供任何形式的数据转发、批量导出或对外服务；如未来以 SaaS 形式向第三方提供，须重新评估行情转发授权。
2. **不做交易**：本期严格不接入任何交易接口（datadir 模式下系统本身就不含交易能力），避免量化交易报备等资质问题；代码评审将「无交易 API 引用」列为门禁。
3. **账号信息安全**：datadir 直读模式无需保存客户端凭据；如未来模式扩展涉及凭据，走项目既有密钥加密服务，日志与接口响应中脱敏。

### A. 异常处理清单

| 场景 | 用户表现 | 处理方式 | 可恢复 |
|------|----------|----------|--------|
| datadir 路径不存在/不可读 | 健康页显示「路径不存在」并回显配置 | 采集任务跳过，熔断计数，回退链接管 | 是（路径修复后周期重检自动恢复） |
| datadir 文件四级自检失败 | 显示「自检失败」并定位具体文件 | 整文件拒读，缺口登记，转 tushare 兜底，绝不写可疑值 | 是 |

| 解析异常（个别文件损坏） | 无感知 | 该文件拒读 + 缺口登记，其余文件继续 | 是 |

| 首次全量中断 | 健康页显示进度与断点 | `sync_checkpoints` 断点续传 | 是 |
| 补采连续 3 轮失败 | 告警 | 停止该缺口自动补采，转人工 | 是 |
