# 投资期限贯通（优化方向二 · 方案 A）

> 2026-10 实施。horizon（short/mid/long）成为贯穿「用户参数 → prompt 锚点 → 结算期限 → 记分卡分组」的一等维度。
> 设计定稿与行业参照（references/ai-hedge-fund、references/TradingAgents）见计划存档；本文档是落地后的实现与使用说明。

## 1. 档位定义（单一事实源 `app/core/horizons.py`）

| 档位 | API 值 | 持有期（交易日） | 中文 | 天数锚 | 默认分析师池 |
|---|---|---|---|---|---|
| 短线 | `short` | 7 | 短线 | 与旧 `DEFAULT_HORIZON_DAYS=7` 及 seeds 三处期限文案零漂移 | 现有默认 5 人（含社媒情绪） |
| 中线 | `mid` | 20 | 中线 | 月度节奏 / MA20 | +基本面分析师，−社媒情绪 |
| 长线 | `long` | 60 | 长线 | 财报季（对齐 ai-hedge-fund pead=60） | 与中线同池（差异由 prompt 锚点承载） |

约束：`market-analyst` / `short-term-capital-analyst` 是下游 required_sources，任何池不可裁。
默认池只作**前端联动建议**（切档时 confirm 询问，可保留自选），后端不下发改写、不改用户显式选择。

## 2. 端到端链路

```
前端表单（SingleAnalysis / BatchAnalysis el-radio-group，默认 short）
  → POST parameters.horizon（AnalysisParameters 校验：非法值 422；缺省 None=旧行为）
  → analysis_service: 非 None 时 config["horizon"]=...；result 文档记 "horizon" 键
  → executor 物化点闭包取 config.get("horizon")，注入 5 个智能体工厂
  → 结算 register_from_result 读 result["horizon"] → horizon_days 落 decision_settlements
  → 记分卡 by_horizon 分组 + /records 按 horizon_days 筛选
```

| 环节 | 位置 |

## 3. Prompt 锚点策略（为什么不改 seeds）

改 `config/seeds/agents.json` 会触发 seeder 覆盖链（hash 变化 → builtin 覆盖升级；用户改过的条目不被覆盖 → 版本分裂），且占位符会在 UI 编辑界面裸露。因此锚点走**运行时拼接**：`build_horizon_anchor()` 产出的指令段 append 到 system prompt 尾部（最高显著位）。

- **仅 mid/long 注入**；`short` / `None` 返回空串 —— 缺省任务的 prompt 与历史字节一致，行为零漂移。
- trader 版逐条点名角色定义硬文案（「未来 3 天买入」「未来 7 天卖出」「持有周期 短线≤7/中线≤30」）要求按 N 交易日重解读；止损锚随档位升级（5/20/60 日均线破位）；建仓窗口分档 3/5/10 交易日。
- 辩手/裁决版重解读「未来 7 天协同性」；不可在 N 日窗口内兑现的论据降权。
- **不注入**：风险组辩手、risk-manager、summary —— 它们评估的交易计划已带期限，避免双重指令打架。

## 4. 结算与记分卡

- **登记**：`horizon_days = horizon_days_of(result["horizon"]) or 7`。旧任务/未指定任务缺该字段 → 落 7 桶，与历史口径无缝衔接。
- **等待上限**：`max_wait_days(N) = max(90, N*2+10)` —— 7/20 → 90（与旧 `_MAX_WAIT_DAYS` 完全一致）；60 → 130 自然日（60 交易日约 84 自然日，翻倍+10 可扛春节+国庆连跨）。`_settle_record` 与 `_days_remaining` 两处**同源**使用，防「剩余天数」与「unfillable 判定」错位。
  - 此前硬编码 90 会让第 85~90 自然日才走完 60 交易日的长线决策被误判 unfillable，已修复并有专项测试。
- **by_horizon 口径**（对齐 ai-hedge-fund）：按 horizon_days **全状态**分组——count / pending / settled 命中率 / avg_return。**pending 只计数不阅卷**：长线决策大部分时间处于待到期状态，把它们计入命中率等于用短窗口阅长线卷。`hit_rate` 分母只含已结算且信号非 Hold 的样本。
- **筛选**：`GET /api/settlement/records?horizon_days=20`（收数值不收枚举，旧记录天然可查）。

## 5. 前端交互

- 单股/批量分析表单：`投资期限` 三选一 radio（默认 短线·7日）。
- 切档到与当前分析师池不一致的档位时，confirm 询问是否同步推荐池（文案列出新增/移除的分析师名；「保留自选」= 只改期限不动池）。池先经当前工作流 `prunableSlugs` 裁剪再应用，随后触发 validate-run 轻校验。
- 任务详情侧栏：分析配置卡新增「投资期限」行（参数无 horizon 时不显示，旧任务不受影响）。
- 结算页：记录 tab 新增持有期筛选 + 持有期列；记分卡 tab 新增「分期限统计」表；错题本复用同一列配置自动继承。
- 数据契约：`api/analysis.ts`、`types/analysis.ts`、`api/settlement.ts`、`api/agentConfigs.ts`（horizon_defaults）已同步。

## 6. 使用说明

单股/批量分析表单选择「投资期限」（默认短线·7 日）：

1. 选**中线·20日 / 长线·60日**时，系统询问是否同步调整为推荐分析师池（中线/长线：+基本面、−社媒情绪；可取消保留自选）。
2. 所有买卖建议、止盈止损、辩论证据将按所选期限表述：长线计划以季度基本面为主锚，技术位只作建仓/止盈节奏；止损位随档位升级到 20/60 日均线级别。
3. 分析完成后，结算自动按对应期限阅卷（第 N 交易日收盘价），未到期在记分卡显示 pending、不计入命中率。
4. 结算页可按期限筛选记录、查看分期限统计表。

## 7. 与选股 style 的正交声明

选股 style（short_term / balanced / value）描述**选股方法论**，horizon 描述**持有期**。价值风格 ≠ 长线持有（价值选出的票也可能短线交易）。两者仅共享「短线/中线/长线」中文词根便于用户理解，**不做映射推导**。

## 8. golden 基线红线

horizon 不进 workflow spec（CompileParams / WorkflowSpec / workflows.json 零改动）、不进 state 顶层键、不进事件序列——`test_golden_equivalence.py` **无需重生成基线**即通过。`test_horizon_prompt.py` 内置 state 键集一致性断言做局部复验。后续任何人改期限功能，不得把 horizon 写进 state 或 spec。

## 9. 方案 B 留缝（本期不实现）

观点级 horizon：Signal 增加 `horizon_days: Optional[int]`（None 序列化省略=向后兼容，ai-hedge-fund 同款手法），唯一键升级 `(task_id, channel, horizon_days)`。当出现「一次分析同时产出多期限观点」的需求时按此实施；本期索引不动。
